## Q&A

### 1. Why static classes instead of value objects?
For M1, the validators are pure functions — no state to encapsulate. A
`NationalInsuranceNumber` value object (wrapping a validated string) would
be the next step if we need to pass validated numbers around the domain.
Static methods keep the API surface minimal for a utility library.

### 2. Why `GeneratedRegex` instead of `new Regex()`?
`[GeneratedRegex]` produces a compile-time generated regex implementation —
no runtime compilation cost, and the pattern is validated at build time.
For a library that may validate thousands of inputs, this avoids the
startup hit of `RegexOptions.Compiled` and the per-call cost of interpreted
mode.

### 3. How does the NI number checksum work? (Trick: there isn't one)
Unlike NHS numbers (Mod-11) or credit cards (Luhn), NI numbers have no
checksum digit. Validation is purely structural: format regex + prefix
rules. This means `IsValid` can only say "could be issued", never "was
issued". The docs are explicit about this limitation.

### 4. Why exclude Q from the first letter if "QQ123456C" is everywhere?
HMRC never issues numbers starting with D, F, I, Q, U, or V. "QQ123456C"
appears in examples and test fixtures precisely because it's guaranteed
*not* to be a real person's number. A strict validator rejects it; a
lenient one accepts it for test convenience. We chose strict (HMRC rules)
and document the decision.

### 5. What's the hardest part of UK postcode validation?
The outward code has 6 valid patterns (A9, A99, AA9, AA99, A9A, AA9A) plus
special cases (GIR 0AA, BFPO). A naive `^[A-Z0-9 ]+$` accepts garbage like
"ZZZ 999". The regex encodes all valid structural patterns per BS 7666.
Full validation would also check against the Postcode Address File (paid),
which is out of scope for a format validator.

### 6. Why `Normalize` throws instead of returning null?
`Normalize` is for when you've already validated (or want the normalized
form or an exception). Returning null would force null-checks on every call
site. Throwing `FormatException` makes invalid input a programming error,
not a runtime condition. `IsValid` exists for the check-then-act pattern.

### 7. Why CPM (Central Package Management)?
Single `Directory.Packages.props` pins all versions. No version drift
between projects, Dependabot updates one file, and `dotnet restore` is
deterministic. For a library that will be consumed by others, reproducible
builds matter.

### 8. Why is `GenerateDocumentationFile` on for the library but off for tests?
NuGet packages should ship XML docs — consumers see IntelliSense
descriptions. Tests don't ship, so requiring XML comments there is just
noise. The `.csproj` override keeps the library strict without burdening
test code.

### 9. What does the CI pack step prove?
`dotnet pack` validates that the `.csproj` NuGet metadata is well-formed
(PackageId, Version, Authors, etc.). If the metadata is broken, pack fails.
This catches packaging errors before we try to publish in P3/M3.

### 10. How would you version this package?
Semantic versioning: MAJOR for breaking API changes (e.g., changing
`IsValid` signature), MINOR for new validators (e.g., adding NHS number),
PATCH for bug fixes (e.g., correcting a regex). Start at 0.1.0 (pre-release
semantics: anything may change), go 1.0.0 when the API is stable.

## Exercise (20 minutes)

**Goal:** Understand why format validation isn't enough.

1. Find a real UK postcode for a place you know (e.g., Buckingham Palace
   is SW1A 1AA). Verify `UkPostcode.IsValid` accepts it.
2. Invent a postcode that *passes* the regex but can't be real — e.g.,
   "ZZ9 9ZZ". Does `IsValid` accept it? (It should — the regex checks
   structure, not existence.)
3. Write down: what's the difference between *syntactic* validity (format)
   and *semantic* validity (actually issued)? Which does this library
   provide? What would you need for the other?
4. Look up the NHS number Mod-11 checksum algorithm. In one paragraph,
   explain how it differs from NI number validation and why checksums
   exist.

**Success criteria:** You can explain to an interviewer why "valid format"
doesn't mean "real identifier", and when each level of validation is
appropriate.
